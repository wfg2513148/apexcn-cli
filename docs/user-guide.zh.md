# apexcn-cli 用户手册

本手册面向通过本地 AI 工具使用 APEX 中文社区的普通用户。你不需要记住命令或参数，只要说明想找什么、想了解什么或想完成什么操作。

## 1. 开始之前

使用 `apexcn-cli` 需要：

- 一台已安装 Node.js 20 或更高版本的电脑；
- 一个 APEX 中文社区账号；
- 该账号的 API Key；
- 一个能够在本机运行命令的 AI 工具。

如果还没有安装，可以把下面的话发给 AI：

> 请帮我安装 apexcn-cli。安装完成后检查版本是否可用。安装阶段不要向我索取 API Key。

API Key 必须由你登录 [APEX 中文社区](https://oracleapex.cn/) 后，在账号菜单的 **API Key 管理** 中复制。

## 2. 第一次绑定 API Key

步骤最少的方式，是在自己的终端中执行：

```bash
apexcn -apikey "YOUR_API_KEY"
apexcn auth audit
```

请把 `YOUR_API_KEY` 替换成真实 Key，不要原样复制。这个方式可能被终端保留在命令历史中。

公共电脑或更重视安全的场景，可以只让 CLI 记住环境变量名：

macOS / Linux：

```bash
export APEXCN_API_KEY="YOUR_API_KEY"
apexcn auth set-token --token-env APEXCN_API_KEY
apexcn auth audit
```

Windows PowerShell：

```powershell
$env:APEXCN_API_KEY="YOUR_API_KEY"
apexcn auth set-token --token-env APEXCN_API_KEY
apexcn auth audit
```

如果忘记方法，运行 `apexcn auth --help` 就能重新看到完整提示。

绑定完成后，可以对 AI 说：

> 请确认 apexcn-cli 当前登录的是哪个社区账号，并检查搜索功能是否可用。不要显示完整 API Key。

## 3. 搜索和阅读社区内容

你可以从宽泛问题开始，让 AI 再帮你缩小范围：

> 请在 APEX 中文社区搜索“APEX REST API”，找出最相关的 5 篇话题，并说明每篇主要解决什么问题。

> 请查找“ORDS 认证失败”相关内容，按“优先阅读、补充阅读、仅供参考”分组。

> 请告诉我最近 7 天有哪些新话题，按板块分类并概括内容。

> 请阅读刚才选中的话题，总结关键步骤、适用条件和注意事项。

返回结果应包含可直接打开的社区链接。转载内容还应单独显示原文链接；引用名称应使用完整话题标题，而不是只显示证据编号。

## 4. 让社区资料帮助回答问题

适合提出的问题包括故障排查、功能用法、学习路线和方案比较：

> 请根据 APEX 中文社区现有内容回答“Oracle APEX 如何调用 REST API”，并为每个关键结论附上参考话题标题和链接。

> 请根据社区讨论整理一份 ORDS OAuth2 Bearer Token 排查清单，按检查顺序排列。

> 请比较刚才 3 篇话题中的解决方法，列出共同点、差异、适用版本和风险。

> 请为初次接触 APEX 的用户整理一条从页面开发到调用 REST API 的学习路线，并推荐社区内容。

AI 应根据真实检索结果作答。如果社区证据不足，应明确说明，而不是补造来源。

## 5. 查看个人看板

个人看板把与你有关的内容放在一起：

> 打开我的个人看板，分别显示我创建的、我回复的、我收藏的和我订阅的内容。

> 只显示我最近创建的话题。

> 显示我最近回复过的内容。

> 只在我收藏和订阅的内容中搜索 ORDS，不要搜索整个社区。

当你特别说明“只在个人看板中搜索”时，AI 不应把范围扩大到整个社区。

## 6. 起草和发布话题

先让 AI 搜索相似内容，可以减少重复提问：

> 我在 APEX 调用 REST API 时遇到 401。请先搜索已有讨论，再帮我起草一篇求助帖，包含环境、操作步骤、实际结果、期望结果和已尝试方法。先不要发布。

准备发布时：

> 请把刚才确认的内容发布到合适的板块。发布前再次显示板块、标题、正文和标签，等我确认后再执行。

发布成功后，AI 应返回社区现有话题页面的可打开链接。

## 7. 修改或删除自己的话题

> 请从我创建的话题中找到目标内容，帮我把标题和正文写得更清楚。先给我预览，不要保存。

> 请删除刚才选中的话题。删除前显示标题、板块、作者和链接，等我确认后执行。

删除属于不可逆操作。目标不明确、内容已经变化或权限不足时，AI 应停止并说明原因。

## 8. 回复和管理回复

> 请为刚才选中的话题起草一条友好回复，补充我的测试结果。先给我预览，不要发布。

> 请回复该话题中的指定留言。先确认目标留言确实属于这个话题，再给我预览。

> 请修改我刚才选中的回复。先显示修改后的内容，等我确认后保存。

> 请删除我刚才选中的回复。删除前确认它属于当前账号并显示完整内容。

回复成功后，AI 应返回可打开的话题或回复页面。

## 9. 收藏、订阅和正确答案

> 请收藏刚才选中的话题，并订阅后续更新。执行前先让我确认目标内容。

> 请取消收藏这个话题，但保留订阅。

> 请显示我收藏的内容，包括收藏的话题和回复。

> 请把刚才选中的回复标记为正确答案。先确认回复内容、当前状态和我的操作权限，再给我预览。

> 请取消这条回复的正确答案标记。

只有具备相应权限的账号才能标记或取消正确答案。CLI 会以社区返回的权限结果为准。

## 10. 为什么写操作要确认两次

发布、修改、删除、收藏、订阅和标记答案采用同一种安全流程：

1. AI 读取当前目标并显示预览；
2. CLI 为这次预览生成一个短操作编号；
3. 你明确确认；
4. AI 使用该编号执行刚才预览的同一项操作。

如果目标内容、账号或状态在确认前发生变化，旧编号不能继续使用，必须重新预览。你不需要自己记录或管理这些编号。

## 11. 理解返回的链接

- **社区链接**：打开 APEX 中文社区中现有的话题、回复或个人页面；
- **原文链接**：仅在内容来自外部文章时出现，用于打开原始来源；
- **受保护页面**：个人请求记录等页面可能要求先在浏览器登录社区。

API Key 用于 CLI 访问接口，不会自动让浏览器也处于登录状态。浏览器提示登录时，请正常登录社区，不要重新生成 API Key。

## 12. 更换 API Key

如果 Key 丢失或疑似泄露，先在社区的 **API Key 管理** 中重新生成，然后重新绑定：

> 请帮助我重新绑定 apexcn-cli 的 API Key。不要在回答、日志或截图中显示完整 Key。完成后验证当前账号。

重新生成后，旧 Key 会立即失效。

## 13. 管理员查看 CLI 运营情况

只有社区管理员账号可以查询 apexcn-cli 调用聚合。可以对 AI 说：

> 查看最近七天 apexcn-cli 调用量、成功数、失败数、异常分布和搜索关键词趋势。

> 按社区用户 ID 查看指定日期范围内的 apexcn-cli 调用异常。不要显示 API Key、请求正文或 ask 问题内容。

结果表示服务端收到的 CLI 请求，不包含本地校验失败或未到达服务端的网络错误。客户端标识用于运营归因，并不是不可伪造的安全身份证明。关键词只统计显式搜索输入；问答正文不会进入关键词趋势。

指定日期范围时必须同时提供开始和结束日期，首尾均计入且最长 90 天。

## 14. 故障排查

可以先对 AI 说：

> apexcn-cli 好像不能用了。请检查安装版本、API Key 配置、当前账号、社区连接和搜索功能，告诉我失败在哪一步。不要输出完整 API Key。

常见情况：

- **找不到 `apexcn`**：重启 AI 工具或终端，再检查安装是否完成；
- **认证失败**：运行 `apexcn auth audit`，必要时重新绑定 Key；
- **网页要求登录**：在浏览器中登录社区，CLI 登录和浏览器登录是两个独立会话；
- **链接无法打开**：保留完整输出并提交 issue，不要手工删除或修改链接参数；
- **写操作没有执行**：检查是否只完成了预览，以及是否明确确认了当前预览。

需要自行查看命令时，可阅读 [命令行终端手册](cli-manual.zh.md)。安全细节见 [安全说明](security-model.md)。
