# 社区 API 修复与 CLI 统计 v2：目标和验收

## 目标

以 2026-11-05 的生产 API、社区仓库最新远端提交和 CLI 1.2.2 为起点，定位并修复已复现的英文搜索故障，恢复可用且完整的 API 契约，为 CLI 增加向后兼容的管理员统计 v2，并在独立验证项目完成真实场景验收。所有适用验收条件通过、证据可追溯，才可关闭本目标。

## 范围与边界

- 社区代码、ORDS、DEV／TEST／生产部署和服务端证据由 `/Users/kwang/apexcn-forums` 的独立可见任务负责；本任务只改 `/Users/kwang/apexcn-cli`。
- 独立验收由 `/Users/kwang/apexcn-cli-test` 的全新可见任务执行。验证者使用冻结包和公开资料，不读实现源码、不修候选，保留首次失败。
- 保留 CLI 的 `admin operations` v1 默认行为、JSON 契约和关键词功能。新增显式的 `admin operations-v2`，只在服务端声明 v2 可用时调用 v2；不可用、无权限、未知契约或损坏响应均不能静默降级为 v1。
- v2 使用上海业务日期、最多 90 天的成对日期、正整数用户 ID 和 `10/20/50/100` 四种 limit；保留服务端的 `schemaVersion: 2`、`semanticsId: AFA-CLI-OPS-1.0`、三分计数、成功率、分类覆盖率、补零日序列及无关键词语义。
- 不自动把英文搜索降级为中文，不使用数据库绕过 ORDS 作为 CLI 功能。凭据只取自批准的安全存储；生产不写入测试业务内容。
- 保留无关工作区修改、既有采集状态和历史测试证据。不把本次验收描述为已经完成历史 GA 资格。
- 向后兼容的新增命令暂定候选版本 `1.3.0`；冻结前重新核对远端版本和标签。未经明确授权不得升级至 2.0.0 或更高。

## 验收条件

## 主要反例

- capability 存在但 `available=false`、缺少 v2 端点、管理员权限被拒绝或服务端声明未知版本。
- v2 把未分类请求计入失败或成功率分母、遗漏无请求日期、使用错误业务时区。
- v2 输出被现有 v1 JSON Schema 错误接纳，或者新命令破坏旧命令的关键词和脚本输出。
- `--limit 11`、单边日期、跨越 91 天、未来日期、无效日期和非正整数用户 ID。
- 英文搜索故障只被静默切换到中文，或 API 成功但真实页面与所选语言不一致。

## 契约发现更正

2026-11-06 的 DEV 实测显示，topic／reply 更新的 PATCH 虽已在 ORDS 注册，却在公开入口返回 nginx 404；POST 对专用样本的实际更新成功，现有 CLI 也使用 POST。生产 PATCH 尚未测试。此前 A03 将已注册的 PATCH 视作已公开可用，这一前提不成立；验收改为如实区分注册、DEV 实际行为与生产未知状态，避免把未验证功能写成可用或为迎合文档而扩大基础设施变更。
